# Scope a Fitted sprint

Use when the user asks to scope, plan, or reassess work. Follow `AGENTS.md` and
`docs/README.md` for product direction and document authority.

Read relevant source, tests, the governing spec sections, and the active sprint plan
before asking questions. Establish the concrete user job, acceptance behavior, major
failure cases, and a bounded implementation/review outcome. Ask only for unresolved
decisions that materially affect product direction, privacy, ownership, deletion,
evidence, or release. Use judgment for routine choices; do not run an exhaustive
interview or require every detail to be resolved before useful work starts.

Preserve the user's requested plan/build/review/debug loop. Record decisions in the
existing active sprint plan or spec when needed; create a new document only when the
user's task and repository guidance call for one.
